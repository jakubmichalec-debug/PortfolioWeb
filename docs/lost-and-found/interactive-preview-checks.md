## Update 2026-10-02 · arrival, waiting, real-prototype links, phone tidy-ups

Four changes after a full test pass of the page (real-time headless Chrome, desktop and touch-emulated phone).

1. **"Try the locker" lands on the machine.** The hero button and the "01 / Try it" nav link are intercepted in `locker-story.js` (`goToLocker`). It scrolls to the highest anchor that still keeps the whole machine on screen below the sticky bars (task cards, then the workbench, then the step guide), moves focus to the workbench so Tab continues on the first control, and also handles a `#try` deep link once the lab has loaded. Before: at 1440 × 900 the machine ended 231 px below the fold and on a 360 × 640 phone neither the machine nor the main button was visible. After: machine and main button are on screen at 1440 × 900, 1366 × 680, 1920 × 960, 820 × 1100, 390 × 844 and 360 × 640. Reduced motion (no Lenis) lands in the same place; a click while the lab is still loading ends in the same place once it mounts.
2. **Rejected cards no longer lock the demo for 6 s.** *Quick feedback* is on by default (checkbox below the sound toggle) and plays only the feedback waits 2.4× faster; unchecking it restores the prototype's real delays. The main button becomes **Skip the wait →** during a feedback wait (the small *Skip this wait* link stays), and one skip now clears both stages of the empty-box wait. Physical steps (opening 1 s, moving the item 0.7 s, closing 1 s) are never sped up or skipped. The timer shows real seconds. Measured lock-out including the 0.35 s card read: unknown card 6.4 s → about 3.2 s (6.7 s with real timing), recognised non-owner 3.4 s → about 1.9 s. The factor is capped at 2.4× because the 100 ms UI tick must still show three distinct red flashes (covered by a test). The helpers live in `js/locker-pacing.js`; the engine file is unchanged.
3. **Real-prototype links.** After a rejected card, a finished collection and a finished storage task, a chip at the top of the machine view offers "Watch … on the real prototype". It plays the matching video chapter (`denied`, `claim`, `master` in `manifest.json`), centred below the sticky bars. Without the chapter list it falls back to the plain `#watch` anchor. The standalone preview has no video section, so the chip is only shown on the case-study page.
4. **Phone tidy-ups.** The section nav uses short labels at ≤ 700 px ("05 Next"), so all five sections fit from 320 px up, also with 1.5× text; if it ever overflows, the active section scrolls into view. On touch screens (`pointer: coarse`) the sound and quick-feedback rows, Restart, the in-scene LED/buzzer hotspot, part tabs, form buttons, hero and hardware buttons, the lightbox close button, the shared footer links, menu button and `.btn` get at least 44 px tap areas. Effective touch targets under 44 px on a 390 px phone: 35–39 before, 5 now (two checkboxes whose 44 px label row is the target, the LED hotspot at 64 × 32, the keyboard-only skip link and the brand link at 38 px high).

## Update 2026-10-05 · focus rework of the "Try it" section

Request: the section had far too many things in one place. Measured before the change (desktop, 1440 px, nothing opened): 26 visible controls, 75 text blocks, about 3,200 characters of text, and a section 2,174 px tall (3,674 px on a 390 px phone). After: 15 controls (7 of them are hotspots on the machine itself), 35 text blocks, about 880 characters, 1,048 px tall (1,385 px on the phone).

**What a visitor sees now.** A two-button task switch (Collect my item / Store a found item), the machine, and one guide: a thin progress bar, the step, one sentence and one yellow button. Below the machine sit three quiet rows that open on demand: *Other cards & options*, *Hardware & code behind each step* and *What's real, what's simulated*. On a phone the guide comes first, so the button sits directly above the machine.

**Where things went.**
- Removed because they repeated something else: the second "Scan my personal card" button above the machine, the "01 / The machine" and "02 / Follow the steps" panel headers, the step chips (now the progress bar), the visible status paragraph (still announced to screen readers), the phase label and timer line (the timer now only appears during a wait), the "Guided mode: no time limit" note, the "Switching tasks starts a fresh example" note, the separate door button and "Move item" button (the door and the main button do both), the description form's own Save button and its repeated hint, the lock badge and the latch close-up (the latch on the machine shows the same state), the small *Skip this wait* link (the main button becomes **Skip the wait →**) and the model note.
- Moved into *Other cards & options*: the four RFID cards, buzzer sound, Quick feedback and the rotate slider. Dragging the machine sideways also rotates it, with a mouse or a finger.
- Moved into *Hardware & code behind each step*: the part explanation and tabs, the code excerpt, the signal log and the "physically inside" list. Clicking a part of the machine (LCD, reader, LED, servo, board) opens this row and scrolls to it; the normal step-by-step updates do not open it.
- Moved into *What's real, what's simulated*: the caveat paragraph, which now also mentions that rejected-card waits are shortened by default.
- Shown only when they matter: the "in your hand" tray (it is also where a taken item lands), the Wallet/Keys tag choice and the description field.
- The task switch is no longer locked mid-task; switching simply starts that task fresh.

**Technical notes.** `previews/locker-demo.html` is the single source for both the case study and the standalone preview. The guide comes first in the DOM, so Tab after "Try the locker" reaches the main button first; on wide screens CSS grid puts the machine on the left. `css/locker-demo.css` now keeps the machine/3D rules first and a single "Focus layout" block at the end (358 → 309 rules: the 143 rules for removed UI are gone, and the five competing `.scene` height rules became one set). Run `node tools/scope_locker_css.mjs` after editing it. After editing the lab's CSS or JS run `python tools/bump_cache_version.py`. Also fixed: in-page links in the mounted lab (the `#watch` chip) were rewritten to point at the standalone preview page.
